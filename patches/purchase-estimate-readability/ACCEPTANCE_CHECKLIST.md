# Purchase + Estimate Readability — Acceptance Checklist

## General

- [ ] Page opens in the same ERP tab/page.
- [ ] No normal workflow uses `window.open()`.
- [ ] Desktop content uses available width instead of a narrow central box.
- [ ] Default 115% comfortable view is readable without browser zoom.
- [ ] Optional 100/115/125 controls work in-page.
- [ ] Selected size preference may persist locally.
- [ ] Screen scaling does not alter server/accounting values.

## Purchase

- [ ] Vendor/header fields are comfortably readable.
- [ ] Inputs/selects are at least ~44px high at comfortable default.
- [ ] Part Code/Name fields are readable.
- [ ] Job Card/Vehicle allocation field is readable.
- [ ] Qty/Rate/Tax/Amount columns do not collapse to tiny text.
- [ ] Large tables horizontal-scroll instead of shrinking text.
- [ ] Header stays visible while scrolling where practical.
- [ ] Totals are visually prominent.
- [ ] Save/Add buttons are easy to hit.

## Estimate Create/Edit

- [ ] Customer/Vehicle header readable.
- [ ] Parts section readable.
- [ ] Labour section readable.
- [ ] Total is prominent.
- [ ] Page does not require separate popup window.

## Estimate Preview

- [ ] Preview uses available page width.
- [ ] Document is centered and visibly larger on screen.
- [ ] Parts appear above Labour where the Estimate follows Workshop order.
- [ ] 115% default can be reduced/increased in-page.
- [ ] Print/PDF uses normal document scale, not screen readability scale.

## Responsive

- [ ] Mobile/tablet keeps readable font sizes.
- [ ] Wide line tables scroll horizontally.
- [ ] Totals stack to full width.
- [ ] No 8–10px body text is used just to force all columns onscreen.
