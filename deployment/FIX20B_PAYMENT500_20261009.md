# FIX20B — Payment Voucher 500 exact fix (09-Oct-2026)

Live read-only diagnostic confirmed:

- route `GET erp/payments/create` exists;
- required tables exist;
- `ExpensePaymentService::payableSources()` fails with MySQL/MariaDB error 1055 under `ONLY_FULL_GROUP_BY`;
- failing area is the Parts Purchase payable-source aggregation.

## Root cause

The live query computes the payment source key as:

`COALESCE(NULLIF(p.purchase_batch_no,''),p.purchase_no)`

and groups directly by the same expression. The staging SQL implementation rejects the selected constituent field under `ONLY_FULL_GROUP_BY`.

## Fix

Do **not** disable SQL mode and do **not** change schema.

Project `src_ref` in an inner query, then aggregate the outer query by the derived `src_ref`.

This preserves:
- one payable source per modern `purchase_batch_no`;
- legacy fallback to `purchase_no`;
- existing `workshop_payment_vouchers.source_reference` matching;
- existing outstanding calculation.
